Privacy

What MoonlightWeb sends

MoonlightWeb runs on your own computer. The picture, sound and input of a stream go straight from your gaming PC to your browser and never pass through our servers. This page lists everything that does reach us, and how to stop it.

What the app sends

Only the official builds send any of this. A build you compile yourself sends none of it to us; its update check goes to GitHub.

  • Update check: at most every six hours, the version, the operating system and the processor type (x64 or ARM) go to updates.moonlightweb.top, which answers with GitHub's latest release.
  • Session counts: when a stream starts and when it ends, its shape: resolution, frame rate, codec, HDR and 4:4:4, bitrate, how it is carried (backend, transport, LAN or Internet), the kind of device, owner or guest, and how long it lasted, or the error code if it never started. With it go the version, the operating system and the processor type. No host name, no account, no app or game, and no address.
  • Error reports: after a stream that hit an error, at most one report every 15 minutes, holding the error and warning lines of the PC and of the browser pages that took part, with the build and the stream's shape. On your PC, addresses, machine and user names, keys, links and app titles are taken out first, and our server filters them again. A report is kept for 90 days at most.

No address is stored. The counts go to our own analytics behind a hash that changes every day, and the servers that receive them keep no access log.

To stop it, use Settings › Privacy in the app. It turns all three off at once, takes effect immediately, and can only be changed from the PC itself; the update check then asks GitHub directly.

In settings.json, "update_relay_enabled": false sends the update check straight to GitHub instead, and "session_metrics_enabled": false stops the counts and the error reports. The MW_NO_TELEMETRY=1 environment variable stops everything, the update check included.

Internet access

Internet access is off until the owner turns it on, in the installer or on the admin page.

Once it is on, the PC keeps one connection open to stream.moonlightweb.top, which introduces a browser to the PC. It relays the connection setup, which carries each side's addresses. The key that secures the stream is vouched for by your PC's pairing key, which this server never sees, so it cannot place itself in the middle. Once the two are connected, it drops out.

It sees the addresses of connected PCs and browsers while they are connected, and writes none down.

It keeps only the PC's identifier, a hash of its owner's token, and when it was created and last online (to the hour). No message is written down.

Feedback

Feedback is sent only when the owner writes a message in the server settings and presses Send. It carries the message, an e-mail address if one was typed, and, only if the box is ticked, the version, the edition and the OS family.

It is posted to a private channel on Discord that the moderators read. Our server keeps no copy.

Other services

  • GitHub: unless MW_NO_TELEMETRY=1 is set, the update check asks api.github.com directly, at most every six hours, whenever it does not go through updates.moonlightweb.top.
  • The Windows installer downloads the ViGEmBus gamepad driver from its project's GitHub release when the PC does not already have it. Uninstalling MoonlightWeb leaves the driver installed.
  • Where a session came from: if the owner sets "session_location_enabled": true, the visitor's address is sent to ipwho.is, so that the admin page can show a city. This is off by default, and private addresses are never sent.
  • This website uses cookieless analytics that we host ourselves. Its download buttons ask GitHub, from your browser, for the latest release. The MWSR page sends its measure only when you press its button, without your address.
